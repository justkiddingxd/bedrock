# Bedrock → Hermes: подключить вебхук напоминаний

Сервер синхронизации Bedrock теперь отправляет каждое сработавшее напоминание `⏰` подписанным POST-запросом на адрес, заданный в аккаунте. Приёмник в Hermes уже написан по контракту. Твоя задача: направить Bedrock на этот приёмник, проверить доставку и довести напоминание до сообщения в Telegram.

## Что есть на стороне Bedrock

- **Сервер:** `http://185.225.191.222:8790` (хост Warsaw). Он работает как systemd-сервис `bedrock-server`, настройки лежат в `/etc/bedrock/server.env`, вход по SSH — `root@185.225.191.222`. Сервер работает по http без TLS. Если ты сам на Warsaw, ходи в API через `http://127.0.0.1:8790`: так секрет не уйдёт в сеть открытым текстом.
- **Аккаунт пользователя:** `sideways`, серверное хранилище `main`, часовой пояс аккаунта UTC+3 (его выставляет приложение). На аккаунт настраивается один вебхук.
- **Когда уходит событие:** по тем же правилам, что Telegram-напоминания:
  - невыполненная строка с `⏰ YYYY-MM-DD HH:MM` в серверном хранилище;
  - время считается по поясу владельца;
  - проверка идёт каждые 15 с;
  - одно напоминание — одно событие.
- **Дубли с ботом Bedrock:** собственный Telegram-бот Bedrock работает независимо от вебхука. Если он тоже привязан, пользователь получит два сообщения: от бота Bedrock и от Hermes. Спроси пользователя, оставить оба канала или отвязать один (Bedrock → «Telegram и Claude» → «Отключить чат»).

## Что нужно до начала

1. **Адрес приёмника Hermes:** полный URL, `http` или `https`.
2. **Секрет приёмника:** не короче 32 символов. Если он короче, сгенерируй новый (`openssl rand -hex 32`) и замени его в Hermes.
3. **API-токен Bedrock:** попроси его у пользователя. Он создаётся в Bedrock → «Телеграм и Claude» → «Создать токен» и показывается один раз.

Токен и секрет не печатай ни в ответах, ни в логах, ни в командах, которые попадут в историю. Держи их в переменных окружения.

Вместо шага 2 пользователь может сам ввести адрес и секрет в приложении: блок «Вебхук напоминаний», затем кнопка «Проверить».

## Шаг 1. Где слушает Hermes

- **Публичный адрес, доступный с 185.225.191.222:** ничего делать не нужно.
- **Hermes на самом Warsaw, на `127.0.0.1` / `localhost`, или в частной сети** (`10.*`, `192.168.*`, `172.16–31.*`): Bedrock такие адреса не вызывает. Это защита от SSRF: регистрация на сервере открыта для всех. Хост нужно разрешить, а это изменение на сервере пользователя, поэтому сначала спроси разрешения:

  ```bash
  ssh root@185.225.191.222
  sed -i 's/^#BEDROCK_WEBHOOK_ALLOW_HOSTS=.*/BEDROCK_WEBHOOK_ALLOW_HOSTS=127.0.0.1/' /etc/bedrock/server.env
  grep WEBHOOK /etc/bedrock/server.env
  systemctl restart bedrock-server && systemctl is-active bedrock-server
  ```

  Хост сравнивается с адресом в URL буквально: `127.0.0.1` и `localhost` — разные значения. Порт не учитывается. Несколько хостов перечисляются через запятую.

## Шаг 2. Сохранить вебхук

```bash
export BEDROCK=http://185.225.191.222:8790   # на самом Warsaw: http://127.0.0.1:8790
export BEDROCK_TOKEN=...   # API-токен от пользователя
export HOOK_URL=...        # адрес приёмника Hermes
export HOOK_SECRET=...     # секрет приёмника

python3 -c 'import json,os; print(json.dumps({"url": os.environ["HOOK_URL"], "secret": os.environ["HOOK_SECRET"]}))' |
  curl -sS -X PUT "$BEDROCK/api/reminder-webhook" \
    -H "Authorization: Bearer $BEDROCK_TOKEN" -H 'Content-Type: application/json' --data-binary @-
```

Ожидаемый ответ: `{"configured":true,"url":"…","last_status":null,"last_delivery_at":null}`. Секрет сервер не возвращает никогда. Чтобы потом сменить только адрес, отправь `{"url": …}` без `secret`: сохранённый секрет останется. Ответ 400 с текстом разобран в разделе «Неполадки».

## Шаг 3. Тестовое событие

```bash
curl -sS -X POST "$BEDROCK/api/reminder-webhook/test" -H "Authorization: Bearer $BEDROCK_TOKEN"
```

Ожидаемый ответ: `{"delivered":true,"status":200,"body":"…","error":null}`. Тест отправляется одной попыткой, без повторов.

У тестового события:
- `"test": true`;
- `task.text` — «Тестовое напоминание из Bedrock», `task.path` — «Тест.md»;
- `vault` — `{"id":"test","name":"Тест"}`;
- `id` каждый раз новый.

По логам Hermes проверь, что подпись принята, а событие с `test: true` обработано так, как вы договорились.

## Шаг 4. Настоящее напоминание

```bash
curl -sS "$BEDROCK/api/vaults" -H "Authorization: Bearer $BEDROCK_TOKEN"   # возьми id у "name":"main"
export VAULT=...
export AT=$(TZ=Europe/Moscow date '+%F %H:%M')   # текущая минута по времени владельца

python3 -c 'import json,os; print(json.dumps({"text": "- [ ] Проверка вебхука ⏰ " + os.environ["AT"]}))' |
  curl -sS -X POST "$BEDROCK/api/vaults/$VAULT/append/webhook-check.md" \
    -H "Authorization: Bearer $BEDROCK_TOKEN" -H 'Content-Type: application/json' --data-binary @-
```

В течение примерно 20 секунд Hermes должен получить событие с такими полями:
- `test: false`;
- `task.text` — «Проверка вебхука», `task.path` — `webhook-check.md`, `task.line` — `0`, `task.priority` — `"normal"`, `task.due` — `null`;
- `X-Request-ID` — hex SHA-256 от строки `"<VAULT>|webhook-check.md|Проверка вебхука|<AT>"`.

После этого пользователь должен получить сообщение в Telegram через Hermes.

Проверь статус: `curl -sS "$BEDROCK/api/reminder-webhook" -H "Authorization: Bearer $BEDROCK_TOKEN"` должен вернуть `"last_status":"доставлено (ответ 200)"`.

Затем убери тестовую заметку (удаление дойдёт до устройств пользователя):

```bash
curl -sS -X DELETE "$BEDROCK/api/vaults/$VAULT/notes/webhook-check.md" -H "Authorization: Bearer $BEDROCK_TOKEN"
```

Напоминание, которое к моменту записи старше 5 минут, не отправляется. Если событие не пришло за минуту, уточни часовой пояс у пользователя.

## Что именно присылает Bedrock (сверь с приёмником)

```http
POST <url>
Content-Type: application/json
User-Agent: Bedrock/0.1.0
X-Request-ID: <id события>
X-Webhook-Timestamp: <unix-время отправки, секунды>
X-Webhook-Signature-V2: <hex HMAC-SHA256 от "<timestamp>.<тело>" с ключом secret>
```

```json
{"event_type":"reminder","id":"…","test":false,"at":"2026-10-31 09:00","at_utc":"2026-10-31T06:00:00Z","vault":{"id":"…","name":"main"},"task":{"text":"Позвонить маме","path":"Дневник/2026-10-31.md","line":4,"due":"2026-10-31","priority":"normal"}}
```

- **Тело** — компактный JSON без пробелов, поля идут в этом порядке. Подпись проверяй по полученным байтам, ничего не пересериализуя.
- **Время:** `at` — местное время владельца, `at_utc` — то же время в UTC, секунды всегда `:00`.
- **Поля задачи:**
  - `task.text` без маркеров (`📅 ⏰ ⏫` и т. п.);
  - `task.line` считается с 0;
  - `priority` для задачи — `high`, `medium`, `normal` или `low` (без отметки — `normal`), для строки, которая не задача, — `null`;
  - `due` равно `null`, если в строке нет `📅`.
- **Повторы:** на `429`, `5xx`, сетевую ошибку или отсутствие ответа за 10 с сервер повторяет запрос через 30 с, 2 мин и 10 мин. Всего 4 попытки, у всех тот же `id`, а timestamp и подпись новые.
- **Постоянная ошибка:** любой другой код, не `2xx` (`400`, `401`, `403`, `404`, `413`, `405`, `422`, `3xx`), — повторов нет. Редиректы сервер не выполняет.
- **Доставлено:** любой `2xx` с любым телом, включая `{"status":"duplicate"}`.
- **Скорость ответа:** отвечай быстрее 10 с. Прими событие, положи его в свою очередь и пересылай в Telegram асинхронно.
- **Часы:** на Warsaw они синхронизируются по NTP. Расхождение больше 5 минут возможно только из-за часов Hermes.

## Неполадки

| Симптом | Причина и что делать |
|---|---|
| `PUT` → 400 «адрес ведёт в локальную или частную сеть» | Шаг 1: разреши хост и перезапусти сервер |
| `PUT` → 400 «не нахожу такой сервер» | Имя из URL не резолвится с Warsaw |
| `PUT` → 400 «секрет вебхука: от 32 символов» или «нужен секрет» | Секрет короче 32 символов или не передан при первой настройке |
| 401 «нужен API-токен» / «сессия недействительна» | Неверный токен Bedrock: попроси у пользователя новый |
| Тест → `status: 401` или `403` | Hermes отверг подпись. Возможные причины: разные секреты, подпись считается не по сырым байтам, расходятся часы Hermes |
| Тест → `status: 404` | Неверный путь в URL приёмника |
| Тест → `error: «не удалось соединиться с получателем»` | Hermes не слушает этот адрес или порт, мешает фаервол, или Hermes слушает `127.0.0.1`, а в URL публичный IP |
| Тест → `error: «получатель не ответил за 10 с»` | Hermes отвечает слишком долго |
| Тест проходит, а настоящее напоминание не приходит | Строка уже выполнена (`[x]`), время старше 5 минут, другой часовой пояс или хранилище не серверное. Смотри `last_status` |

Логи Bedrock: `journalctl -u bedrock-server -f | grep webhook`. В них пишутся только id события, код ответа и номер попытки.

## Готово, когда

- Тест вернул `delivered: true`, и Hermes принял подпись.
- Настоящее напоминание дошло до Telegram через Hermes, а `last_status` показывает «доставлено (ответ 200)».
- Тестовая заметка удалена, токен и секрет нигде не напечатаны.
- Пользователь решил, оставлять ли параллельно бота Bedrock.
