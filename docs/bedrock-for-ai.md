# Bedrock: гайд для ИИ-ассистента (MCP и REST API)

Этот документ — инструкция для языковой модели, которая работает с заметками и задачами пользователя в Bedrock. Его можно целиком вставить в системный промпт или в базу знаний проекта.

---

## 1. Что такое Bedrock

Bedrock — приложение для заметок и задач, совместимое с Obsidian. **Хранилище** (vault) — это папка с Markdown-файлами. Всё, что ты делаешь через инструменты, меняет эти файлы. Приложение пользователя подхватывает правки сразу, а синхронизация разносит их по устройствам и участникам общего хранилища.

Есть два способа доступа:

| Способ | Где работает | Какие хранилища |
|---|---|---|
| **Локальный MCP** (`bedrock-mcp`, stdio) | на компьютере пользователя | одна папка-хранилище, любая |
| **Удалённый MCP** (HTTP) и **REST API** | на сервере синхронизации | только хранилища в режиме «Серверное» |

Хранилища в режиме «Зашифрованное (E2E)» сервер прочитать не может. Удалённый MCP и REST API их не видят, с ними работает только локальный MCP.

## 2. Формат заметок — соблюдай его точно

**Пути** — относительно корня хранилища, через `/`, с расширением `.md`: `Работа/План.md`. Заметки в корне хранилища приложение показывает в разделе «Без папки». Пути с `..` и скрытые папки (`.bedrock`, `.trash`) запрещены. В названиях файлов нельзя использовать `\ / : * ? " < > |`.

**Заметка дня** лежит в `Дневник/YYYY-MM-DD.md`, например `Дневник/2026-10-30.md`.

**Задача** — строка списка с чекбоксом (формат плагина Obsidian Tasks):

```markdown
- [ ] Отправить отчёт ⏫ 📅 2026-11-02
- [x] Купить молоко ✅ 2026-10-29
```

| Маркер | Значение |
|---|---|
| `- [ ]` / `- [x]` | не выполнена / выполнена |
| `📅 YYYY-MM-DD` | срок |
| `⏳ YYYY-MM-DD` | запланировано на дату |
| `✅ YYYY-MM-DD` | дата выполнения (ставится при отметке) |
| `⏫` / `🔼` / `🔽` | высокий / средний / низкий приоритет |

**Напоминание** — маркер `⏰ YYYY-MM-DD HH:MM` в любой строке, время местное, 24-часовое:

```markdown
- [ ] Позвонить маме 📅 2026-10-31 ⏰ 2026-10-31 09:00
```

В назначенное время приложение показывает уведомление, а Telegram-бот присылает сообщение. Напоминание у выполненной задачи (`- [x]`) не срабатывает. Для серверных хранилищ время считается в часовом поясе владельца хранилища.

**Прочее:**
- ссылки между заметками: `[[Заметка]]`, `[[Папка/Заметка]]`, `[[Заметка#Заголовок]]`, `[[Заметка|текст ссылки]]`;
- метки: `#работа`, вложенные `#проект/bedrock`;
- YAML-frontmatter в начале файла между `---`;
- если в заметке есть заголовок `## Задачи`, новые задачи добавляются в конец этого раздела.

## 3. Подключение

### Локальный MCP (Claude Code, Claude Desktop)

Программа `bedrock-mcp` ставится вместе с приложением рядом с `Bedrock.exe`: MSI ставит в `C:\Program Files\Bedrock`, установщик `setup.exe` — в `%LOCALAPPDATA%\Bedrock`. Готовые команды с точными путями приложение показывает в разделе «Telegram и Claude»; ниже — пример.

```bash
claude mcp add bedrock -- "C:\Program Files\Bedrock\bedrock-mcp.exe" --vault "C:\Заметки"
```

Claude Desktop → Settings → Developer → Edit Config:

```json
{
  "mcpServers": {
    "bedrock": {
      "command": "C:\\Program Files\\Bedrock\\bedrock-mcp.exe",
      "args": ["--vault", "C:\\Заметки"]
    }
  }
}
```

Вместо `--vault` можно задать переменную окружения `BEDROCK_VAULT`. Удалённые заметки уходят в корзину хранилища (`.trash`), их можно вернуть.

### Удалённый MCP (claude.ai, любой MCP-клиент по HTTP)

Нужен API-токен: приложение → «Telegram и Claude» → «Создать токен», либо `POST /api/tokens` (см. раздел 6).

- `POST http://185.225.191.222:8790/mcp` с заголовком `Authorization: Bearer <токен>`;
- или `POST http://185.225.191.222:8790/mcp/<токен>` — для клиентов, которым можно дать только URL (например, «свой коннектор» в claude.ai).

Транспорт — Streamable HTTP без SSE: на каждый JSON-RPC запрос приходит JSON-ответ, на уведомления — `202`, `GET /mcp` отвечает `405`. Поддерживаемые версии протокола: `2025-06-18`, `2025-03-26`, `2024-11-05`.

## 4. Инструменты MCP

Все инструменты возвращают текст: обычно это JSON, а `read_note` возвращает саму заметку. Ошибка приходит как результат с `isError: true` и понятным текстом на русском — прочитай его и исправь вызов, не повторяй тот же запрос вслепую.

У удалённого MCP есть ещё `list_vaults`, а у каждого инструмента — необязательный параметр `vault` (имя или id хранилища). Если серверное хранилище у аккаунта одно, `vault` можно не указывать.

Параметр `path` везде принимает полный путь (`Работа/План.md`), путь без `.md` (`Работа/План`) или просто название, если оно уникально (`План`).

### Заметки

| Инструмент | Параметры | Результат |
|---|---|---|
| `list_vaults` *(только удалённый)* | — | `[{id, name, role}]`, role: `owner` / `editor` / `viewer` |
| `list_notes` | `folder?`, `limit?` (100) | `{total, notes: [{path, updated}]}`, сначала недавно изменённые |
| `read_note` | `path` | `Path: <путь>` и полный текст заметки |
| `search_notes` | `query`, `limit?` (30) | `[{path, line, text}]` — совпавшие строки (до 3 на заметку), без учёта регистра; `line: null` — совпало только название |
| `create_note` | `title`, `content?`, `folder?` | `{path}`; если название занято, добавится « 1», « 2»… |
| `write_note` | `path`, `content` | `{path, created}` — **заменяет весь текст**, создаёт заметку, если её нет |
| `edit_note` | `path`, `old_text`, `new_text` | `{path}`; `old_text` должен встречаться ровно один раз |
| `append_to_note` | `path`, `text` | `{path}`; дописывает строку в конец, создаёт заметку при необходимости |
| `delete_note` | `path` | `{deleted}` |
| `daily_note` | `date?` (YYYY-MM-DD, по умолчанию сегодня) | `{path, exists, content}`; ничего не создаёт |

### Задачи и напоминания

| Инструмент | Параметры | Результат |
|---|---|---|
| `list_tasks` | `status?`: `open` (по умолчанию) / `done` / `all`; `path?`; `due_before?` (YYYY-MM-DD, включая просроченные) | `{total, tasks: [{path, line, text, done, due, priority, done_date}]}`, сначала задачи со сроком |
| `add_task` | `text`, `due?` (YYYY-MM-DD), `priority?`: `high` / `medium` / `normal` / `low`, `path?` | `{path, line, task}`; без `path` задача попадает в заметку дня |
| `complete_task` | `path`, `line?`, `text?`, `done?` (по умолчанию `true`) | `{path, line, text, done}`; ставит `- [x]` и `✅ <сегодня>`, при `done: false` снимает отметку |
| `add_reminder` | `text`, `at` (`"YYYY-MM-DD HH:MM"`, местное время), `path?` | `{path, line, at}`; пишет задачу `- [ ] text 📅 дата ⏰ дата время` |
| `list_reminders` | — | `[{path, line, at, text}]` — невыполненные, по времени |

`line` — номер строки **с нуля**. В `text` у задач уже нет маркеров (дат, приоритета, ⏰).

## 5. Как действовать: рецепты и правила

**Что у меня на сегодня.** `list_tasks` с `due_before = <сегодня>` (сюда войдут и просроченные), затем `daily_note`. Сегодняшнюю дату бери из контекста разговора. Если её там нет, вызови `daily_note` без даты: в ответе будет путь с сегодняшней датой.

**Добавить задачу.** Переводи слова пользователя в параметры: «до пятницы» → `due` с датой ближайшей пятницы, «срочно» / «важно» → `priority: "high"`. В `text` пиши только суть, без даты и слов про срочность. Если пользователь назвал заметку или проект, передай `path`, иначе задача уйдёт в заметку дня.

**Отметить выполненной («маркни как готово»).**
1. `list_tasks` — найди задачу, запомни `path` и `line`.
2. `complete_task` с этими `path` и `line`. Добавь `text` (часть текста задачи): если строки сдвинулись, инструмент заметит несовпадение и найдёт задачу по тексту.
3. Если задача известна только по словам («отметь молоко»), можно сразу вызвать `complete_task` с `path` и `text`.

**Напоминание.** «Напомни завтра в 9 позвонить маме» → `add_reminder(text: "Позвонить маме", at: "<завтра> 09:00")`. Время — местное время пользователя в 24-часовом формате. Если время не названо, уточни его или возьми 09:00 и скажи об этом.

**Правка заметки.**
- Маленькое изменение — `read_note`, затем `edit_note` с фрагментом, который встречается один раз (возьми пару слов вокруг).
- Добавить в конец — `append_to_note`.
- `write_note` заменяет файл целиком. Используй его только для новой заметки или когда пользователь просит переписать всё. Перед этим прочитай заметку и сохрани всё, что не нужно менять.

**Поиск.** `search_notes` по ключевым словам, затем `read_note` найденных заметок. Не придумывай пути: бери их из `list_notes` и `search_notes`.

**Правила:**
- После каждой записи номера строк могут сдвинуться. Перед следующим `complete_task` обнови список задач.
- `delete_note` и полную перезапись (`write_note`) делай только по явной просьбе пользователя.
- Пиши даты в формате ISO (`2026-10-30`), время — `HH:MM`.
- Соблюдай формат из раздела 2. Не добавляй свои маркеры и не меняй чужое оформление.
- Роль `viewer` в общем хранилище даёт только чтение: запись вернёт ошибку, скажи об этом пользователю.
- Общие хранилища видят и правят другие люди. Твои изменения увидят все участники.
- Ответ пользователю пиши человеческим языком: «Добавил задачу „Отправить отчёт“ на пятницу в заметку „План“», без JSON.

## 6. REST API (для скриптов, ботов и агентов без MCP)

Базовый адрес: `http://185.225.191.222:8790`. Тела запросов и ответов — JSON. Ошибки приходят как `{"error": "текст"}` с кодами `400` (неверный запрос), `401` (нужен или устарел токен), `403` (нет прав), `404` (не найдено), `409` (конфликт).

Авторизация — заголовок `Authorization: Bearer <токен>`. Подходит и токен входа, и именованный API-токен.

**Кириллица в путях:** кодируй каждый сегмент пути (`encodeURIComponent`), разделители `/` оставляй как есть. В curl на Windows/Git Bash отправляй тело в UTF-8 (файлом через `--data-binary @file.json`): иначе кириллица в JSON может испортиться.

### Аккаунт и токены

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /api/health` | — | `ok` |
| `GET /api/info` | — | `{name, version, protocol, registration_open, max_file_mb, telegram_bot}` |
| `POST /api/auth/register` | `{username, password}` | `{token, username}`; логин 3–32 символа (латиница, цифры, `_-.`), пароль от 8 символов |
| `POST /api/auth/login` | `{username, password}` | `{token, username}` |
| `POST /api/auth/logout` | — | завершает сессию; именованные токены не трогает |
| `PUT /api/me` | `{tz_offset_min}` | часовой пояс: местное время минус UTC, в минутах (Москва — 180) |
| `GET /api/tokens` | — | `[{id, name, created_at}]` |
| `POST /api/tokens` | `{name}` | `{id, name, token}` — токен показывается один раз |
| `DELETE /api/tokens/{id}` | — | отзывает токен |

### Хранилища и участники

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /api/vaults` | — | `[{id, name, created_at, head_seq, mode, role, owner}]` — свои и общие |
| `POST /api/vaults` | `{name, mode: "server"}` | новое серверное хранилище (для `e2e` нужен ключ — его создаёт приложение) |
| `GET /api/vaults/{id}` | — | подробности хранилища |
| `DELETE /api/vaults/{id}` | — | удаляет хранилище (только владелец) |
| `GET /api/vaults/{id}/members` | — | `[{username, role}]`, владелец первым |
| `POST /api/vaults/{id}/members` | `{username, role: "editor" \| "viewer"}` | пригласить или сменить роль (только владелец) |
| `DELETE /api/vaults/{id}/members/{username}` | — | убрать участника; участник может убрать себя (выйти) |

### Заметки (только серверные хранилища)

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /api/vaults/{id}/notes` | — | `[{path, size, seq, updated_at}]` — все файлы |
| `GET /api/vaults/{id}/notes/{path}` | — | `{path, content, seq, updated_at}` |
| `PUT /api/vaults/{id}/notes/{path}` | `{content, base_seq?}` | `{path, seq}`; создаёт или заменяет. С `base_seq` запись пройдёт, только если заметка не менялась с этой версии, иначе `409`. `base_seq: 0` — создать, только если такой заметки нет |
| `DELETE /api/vaults/{id}/notes/{path}` | — | удаляет заметку |
| `POST /api/vaults/{id}/append/{path}` | `{text}` | `{path, seq}`; дописывает строку в конец |
| `GET /api/vaults/{id}/tasks?status=&path=&due_before=` | — | как `list_tasks` |
| `POST /api/vaults/{id}/tasks` | `{text, due?, priority?, path?}` | как `add_task` |
| `POST /api/vaults/{id}/tasks/complete` | `{path, line?, text?, done?}` | как `complete_task` |
| `GET /api/vaults/{id}/reminders` | — | как `list_reminders` |

Безопасная правка заметки через API: `GET` (запомни `seq`) → измени текст → `PUT` с `base_seq: <seq>`. На `409` перечитай заметку и повтори правку.

### Вебхук напоминаний

Сервер может отправлять каждое напоминание из серверных хранилищ подписанным POST-запросом на адрес аккаунта: своему агенту, боту или автоматизации. Правила те же, что у Telegram: невыполненная строка с `⏰`, время по часовому поясу владельца, получатели — все участники хранилища, у кого настроен вебхук. Работает независимо от Telegram: если настроено и то и другое, приходит в оба места. Напоминания зашифрованных хранилищ в вебхук не уходят.

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /api/reminder-webhook` | — | `{configured, url, last_status, last_delivery_at}`; секрет не возвращается никогда |
| `PUT /api/reminder-webhook` | `{url, secret}` | сохранить; `url` только `http`/`https`, `secret` от 32 символов. Без `secret` меняется только адрес, сохранённый секрет остаётся |
| `DELETE /api/reminder-webhook` | — | отключить; неотправленные события отменяются |
| `POST /api/reminder-webhook/test` | — | отправить тестовое событие сразу, без повторов: `{delivered, status, body, error}` — код и начало ответа получателя или текст ошибки |

`last_status` — итог последней попытки словами («доставлено (ответ 200)», «ответ 503, повтор через 2 мин», «отклонено (ответ 401), повторов не будет»), `last_delivery_at` — её время (unix, секунды). Адреса в локальной или частной сети (`127.0.0.1`, `10.*`, `192.168.*` и т. п.) сервер не вызывает, если администратор не разрешил хост в `BEDROCK_WEBHOOK_ALLOW_HOSTS`.

Что приходит получателю:

```http
POST <url>
Content-Type: application/json
X-Request-ID: <id события>
X-Webhook-Timestamp: <unix-время отправки, секунды>
X-Webhook-Signature-V2: <hex HMAC-SHA256 от "<timestamp>.<тело>" с ключом secret>
```

```json
{
  "event_type": "reminder",
  "id": "<тот же id>",
  "test": false,
  "at": "2026-10-31 09:00",
  "at_utc": "2026-10-31T06:00:00Z",
  "vault": {"id": "...", "name": "main"},
  "task": {"text": "Позвонить маме", "path": "Дневник/2026-10-31.md", "line": 4, "due": "2026-10-31", "priority": "normal"}
}
```

- `at` — местное время владельца, `at_utc` — то же в UTC. `task.text` без маркеров (`📅 ⏰ ⏫` и т. п.), как в `list_reminders`. `task.line` считается с 0, как в `list_tasks`. `due` и `priority` (`high`, `medium`, `normal`, `low`) равны `null`, если строка не задача; у задачи без отметки приоритета — `"normal"`.
- `id` = hex SHA-256 от `"<vault_id>|<path>|<task.text>|<at>"`: одинаковый во всех повторах одного напоминания, так что повторы можно отбрасывать по `X-Request-ID`. Тестовое событие: `"test": true`, текст «Тестовое напоминание из Bedrock», путь «Тест.md», `vault` — `{"id": "test", "name": "Тест"}`, `id` каждый раз новый.
- Подпись считается от точных байтов тела. При каждом повторе `X-Webhook-Timestamp` новый, и подпись пересчитывается.
- Ответы: `2xx` — доставлено. `429`, `5xx`, ошибка сети или нет ответа за 10 с — повтор через 30 с, 2 мин и 10 мин, потом сервер сдаётся. Любой другой код (`400`, `401`, `403`, `404`, `413`, редиректы) — постоянная ошибка, без повторов. Очередь хранится в базе: перезапуск сервера события не теряет, доставленное повторно не отправляется.

Проверка на стороне получателя (Python):

```python
expected = hmac.new(secret.encode(), f"{timestamp}.".encode() + raw_body, hashlib.sha256).hexdigest()
ok = hmac.compare_digest(expected, signature) and abs(time.time() - int(timestamp)) <= 300
```

Маршруты `/changes`, `/push`, `/events` служат протоколом синхронизации приложений. Для правки заметок их не используй: работай через `/notes` и инструменты.

### Примеры

```bash
# Получить токен
curl -s -X POST http://185.225.191.222:8790/api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"leon","password":"..."}'
```

## 7. Ограничения

- Файл — до 64 МБ.
- «Сегодня» на сервере (заметка дня по умолчанию, дата в `✅`) и время напоминаний считаются по часовому поясу владельца хранилища. Приложение выставляет его само. Для аккаунта, который работает только через API, задай пояс один раз: `PUT /api/me` с `{"tz_offset_min": 180}`. Без этого используется UTC.
- Правки через API и MCP сразу видят все устройства и участники. Если кто-то правит ту же заметку одновременно, приложение сводит изменения построчно. При конфликте в одной и той же строке рядом сохраняется копия «(conflict …)».
- Сервер сейчас работает по `http` без шифрования канала: не передавай токены через общие сети и не публикуй их.
